# KCH Bakery: Shared Data Shapes

All data lives in `localStorage` and is accessed **only** through `shared/store.js`.
Never read or write the keys directly from an app.

**Important:** both apps must be served from the same origin (same host and port),
e.g. `http://localhost:5500`, otherwise they will not see each other's data.

```js
import { getOrders, updateOrder, getProducts, saveProducts, getRules, saveRules, onDataChange }
  from '../shared/store.js';   // adjust the path for your folder
```

## localStorage keys

| Key            | Contains                  |
|----------------|---------------------------|
| `kch_products` | array of Product objects  |
| `kch_orders`   | array of Order objects    |
| `kch_rules`    | one Rules object          |
| `kch_myOrderIds` | customer app only (which orders belong to this browser) |

## Product

```js
{
  id: 'c02',                 // unique string
  name: 'Red Velvet',
  price: 2200,               // KES. Per kg for cakes, per piece otherwise
  packPrice: 260,            // KES for a pack, or null if no pack is sold
  unit: 'kg',                // 'kg' | 'each'
  minQty: 1,
  category: 'Cakes',         // Cakes | Bread | Buns & Pastries | Cakes & Cookies
  image: '',                 // optional image path
  available: true            // false hides it from the customer menu
}
```

## Order

```js
{
  id: 'KCH-LX3F9A',          // generated by addOrder()
  customer: { name: 'Jane', phone: '0712345678' },
  items: [
    { productId: 'c02', name: 'Red Velvet', unit: 'kg', price: 2200, qty: 2 }
  ],
  total: 4400,               // KES, calculated when the order is placed
  pickupDate: '2026-10-10',  // YYYY-MM-DD
  pickupTime: '10:00',       // HH:MM (24h)
  status: 'pending',         // see statuses below
  cancelRequested: false,    // set true by the customer app
  createdAt: '2026-10-04T09:30:00.000Z',
  updatedAt: '2026-10-04T09:30:00.000Z'
}
```

### Order statuses

`pending` → `confirmed` → `baking` → `ready` → `collected`

or `cancelled` (staff only).

### Cancellation flow

1. Customer clicks "Request cancellation", which sets `cancelRequested: true`. The status does **not** change.
2. Staff review the request. To approve: `updateOrder(id, { status: 'cancelled' })`.
   To reject: `updateOrder(id, { cancelRequested: false })`.

Cancelled orders do not count towards daily capacity.

## Rules

```js
{
  leadTimeHours: 24,         // minimum notice between ordering and pickup
  dailyCapacity: 20,         // maximum non-cancelled orders per pickup date
  hours: {                   // 0 = Sunday ... 6 = Saturday, null = closed
    0: null,
    1: { open: '08:00', close: '17:00' },
    /* ... */
    6: { open: '09:00', close: '13:00' }
  },
  closedDates: ['2026-12-25'] // extra days off, YYYY-MM-DD
}
```

## Functions available from store.js

| Function | Used by | What it does |
|----------|---------|--------------|
| `initStore()` | both | Seeds default data on first run. Call once on page load |
| `getProducts()` / `saveProducts(list)` | staff writes | Read or replace the product list |
| `getRules()` / `saveRules(rules)` | staff writes | Read or replace the rules |
| `getOrders()` | both | All orders |
| `addOrder({customer, items, pickupDate, pickupTime})` | customer | Creates an order with status `pending` |
| `updateOrder(id, changes)` | staff | Merge changes into an order, refreshes `updatedAt` |
| `requestCancellation(id)` | customer | Sets `cancelRequested: true` |
| `ordersOnDate(date)` | both | Non-cancelled orders for a date |
| `isDayFull(date)` / `isDayOpen(date)` | both | Capacity and opening-hours checks |
| `meetsLeadTime(date, time)` | both | Checks the lead-time rule |
| `onDataChange(callback)` | both | Runs when the *other* browser tab changes data |

## Notes for the staff app

- To change an order's status: `updateOrder(order.id, { status: 'ready' })`.
- To update prices, add or hide items: edit the list from `getProducts()` and call `saveProducts(list)`.
- The `storage` event only fires in other tabs, so after saving something in your own tab, re-render it yourself.
- Keep ids unique and never reuse them.
